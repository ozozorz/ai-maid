# 手动验收场地

管理员在主世界输入：

```text
/maid test-scene
```

生成一个 31×31 的空中平台，并将执行者传送到中心。场地位于覆盖范围内最高方块上方，有地基、护栏和照明，不清空地形、不移动现有女仆，不修改游戏规则、难度或时间。缺少已加载区块、接近建造高度上限、超出世界边界或占用范围内存在方块/实体时拒绝生成。主世界的存活、非旁观且未乘坐载具的玩家才能使用；权限与管理员命令一致。

**每次执行都会新建一处场地，不是重置旧场地。** 场地和实体正常保存在世界中，不自动清除。可在专用测试存档使用。

命令属于 Core，不要求安装 LLM 或工作 Addon。缺少 Addon 时会提示，对应工作不会凭空出现。完整测试环境从仓库根目录启动：

```powershell
.\gradlew.bat -p dev/devrun runClient
```

## 场地内容

中心的 **Test Maid** 归执行者所有，开启正常 AI，初始命令为待命。背包已有铁斧、小麦种子、胡萝卜、马铃薯、甜菜种子及小麦。中心木桶提供备用材料和回血用面包；木桶不属于搬运目标，不干扰分类箱。

| 区域 | 内容 | 操作 |
| --- | --- | --- |
| 中心道路 | 待命女仆、说明牌、补给木桶 | 聊天、状态查询、待命/跟随、GUI、补给 |
| 西北橙色 | 单块原木、3 格树干的小树、6 格树干的高树 | 先带女仆走近，再选择单块或整树伐木；高处够不到的原木仍会跳过 |
| 东北绿色 | 四种作物，含成熟、幼苗和空耕地；含水半砖灌溉 | 在田边下令耕种，建议半径 8；观察收获和补种 |
| 西南黄色 | 围栏、圈门、两只可繁殖的成年牛 | 打开圈门，用跟随带女仆进入，再下令喂养；消耗真实小麦，保留原版繁殖冷却 |
| 东南蓝色 | 铜箱含 16 苹果和 16 圆石；两个普通目标箱各有 1 个样品 | 带女仆到箱子旁下令搬运，建议半径 12；完成后目标箱各有 17 个对应物品 |

彩色地块只标记区域，工作中心仍在**下令时女仆所在的位置**。说明牌不会替你自动发出工作命令。搬运测试时关闭箱子界面，以免真实的“有人正在使用容器”规则暂停工作。工作 Addon 仍遵守 `mobGriefing` 等现有规则；生成场地不会强行开启这些规则。

## 自然语言验收顺序

先完成 LLM 配置及 `/maid llm reload`。场地生成不会读取密钥、启用服务或自动请求模型。

1. `/maid chat`，连续聊天两轮，验证连接和会话历史。
2. 发送“跟我来，保护我”，带女仆走一小段，再发送“在这里待命”。
3. 发送“查看你的背包和装备”，对照 GUI 中的真实物品。
4. 带她到对应区域后，依次测试“只砍一块原木”“砍一棵能走近的树”“照料半径 8 格的耕地”“喂养半径 8 格的成年家畜”“按铜傀儡的方式搬运半径 12 格内的物品”。一次消息只选择一种工作。
5. 核对独立的“服务器已接受命令”记录、GUI 命令/停工原因，以及世界或物品的实际变化。模型的口头回答不是完成凭据。

停工用 `/maid command stay`；取消尚未完成的模型请求用 `/maid llm cancel`，取消请求不会撤销已执行的游戏动作。多处场地可能有同名女仆，使用默认最近目标或 `/maid uuid <uuid> ...`，避免名字歧义。

## 自动化验证

- Core `TestSceneGameTests` 检查物品、所有权、待命、作物/灌溉/分类箱，以及权限、已有方块/实体、重复占用和高度限制。
- 整合环境 `TestSceneClientGameTest` 用真实 `/maid test-scene` 生成场地，验证传送、菜单镜像、两棵树的识别，并通过真实服务器命令执行单块伐木、耕种、喂养和分类搬运。
- 自动化验证使用临时世界，不调用真实模型；自然语言理解仍需使用自己的模型服务在游戏中验收。
