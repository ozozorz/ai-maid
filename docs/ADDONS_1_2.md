# 工作 Addon：使用、迁移与验收

目标环境：Minecraft 26.2、Java 25、Fabric Loader 0.19.3、Fabric API 0.158.0+26.2。当前 Core、Lumber、Farming 为 1.3.0，Feeding、Hauling 保持 1.2.1。本文描述持续工作模式；新增有限动作与自主目标执行见 [自主任务架构](AUTONOMOUS_TASKS.md)。

## 模组组成

| 模组 | Maven artifact / JAR 名称前缀 | 作用 |
| --- | --- | --- |
| Core | ai-maid | 实体、背包、装备、GUI、动画、喂食回血、跟随与 PvE 战斗 |
| Lumber | ai-maid-lumber | 一棵树内连续逐块伐木，或明确的单块模式 |
| Farming | ai-maid-farming | 四种普通作物收获、补种、在空耕地播种 |
| Feeding | ai-maid-feeding | 给范围内可繁殖的成年家畜喂食 |
| Hauling | ai-maid-hauling | 参考铜傀儡，从铜箱向空箱或同类物品箱分类搬运 |

四个 Addon 都只依赖 Core，不互相依赖。根目录启动只加载 Core；`dev/devrun` 加载 Core 和四个正式 Addon。测试用巡逻只在 devrun 的 gametest 源集中注册，菜单中隐藏，正式运行与发布 JAR 都不包含它。

## 从 TestAddon 升级

1. 关闭游戏／服务器，从两端 mods 目录移除旧 `testaddon-*.jar`。
2. 安装 `ai-maid-1.3.0.jar` 和需要的正式 Addon JAR；两端版本和模组列表保持一致。
3. 已保存的 `testaddon:guard` 和 `testaddon:patrol` 转为 `ai-maid:follow`；`testaddon:attack` 转为 `ai-maid:attack`。
4. 安装 Lumber 时，`testaddon:lumber` 转为 `ai-maid-lumber:lumber`。旧有限任务不恢复砍伐进度，需要重新选择伐木。

如果未安装对应 Addon，合法但未知的原命令 ID 仍保留，运行时回退跟随并显示缺失命令提示。物品、主人和装备的存档格式保持原有权威存储。旧 TestAddon 巡逻参数不再用于正式功能。

旧数据包若覆盖 `testaddon:combat_targets` / `combat_ignored`，应改为 `ai-maid:combat_targets` / `combat_ignored`；伐木标签改为 `ai-maid-lumber:lumber_logs` / `lumber_soil`。

## Core 战斗

跟随包含自身反击、保护受伤的主人、协助主人攻击。主动战斗在此基础上主动寻找范围内的敌对生物。两者共享近战、弓／弩、真实武器与弹药、追击限制、失败冷却和友方保护，不新增单独“守卫”按钮。

自由和待命不主动进入这套战斗。四个工作命令只因自身遇袭中断，不响应主人远处的战斗。工作遭遇战以遇袭位置为中心限制追击；目标失效、失去视线或追击失败后恢复原工作命令。

## 命令与工作区域

主人可通过 GUI 选择，也可使用以下指令；同样支持 nearest、selector、uuid、name 目标入口。

```text
/maid command follow
/maid command attack
/maid command ai-maid-lumber:lumber
/maid command ai-maid-lumber:lumber single
/maid command ai-maid-farming:farm 8
/maid command ai-maid-feeding:feed 8
/maid command ai-maid-hauling:haul 32
```

耕种、喂养和搬运在选择命令时，以**女仆当前所在方块**设定工作中心。可先让她跟随到工作区，再选择工作。参数为水平半径；省略时使用该女仆已保存半径或默认值。GUI 使用已保存参数。重选会重设中心，不会改变未指定的半径。

| 命令 | 默认半径 / 范围 | 竖直范围 | 运行方式 |
| --- | --- | --- | --- |
| 耕种 | 8 / 2..16 | 中心上下 2 格 | 持续检查，缺种子或空间时等待 |
| 喂养 | 8 / 2..16 | 中心上下 4 格 | 持续检查，缺饲料或无合格动物时等待 |
| 分类搬运 | 32 / 2..32 | 中心上下 8 格 | 持续分类，没有可用箱子时等待 |

这些工作只访问已加载范围，不强制加载区块或跨维度寻找目标。配置中心与半径持久化；当前寻路和短期交互不持久化。工作区域与当前维度不同时会提示重新选择。`mobGriefing=false`、被拴住或乘坐时暂停。

## 伐木

使用原来已经验收的连续伐木实现，迁出测试命名空间：主手需要可用斧头，积累硬度／工具速度驱动的破坏进度，播放挥动与裂纹，完成时才扣耐久并生成一次掉落。

默认识别一棵有限范围的树。严格逐块寻找实际可达站位并检查伸手距离和视线；够不到的高处原木跳过，不在树根远程连锁破坏，不搭建方块。`single` 明确只处理一块。树识别是结构启发式，不保证识别所有模组树，也不能绝对区分天然树与仿树建筑。

被攻击时保留剩余队列、暂停有限任务时钟，清除裂纹和旧目标；战后重新取工具、规划站位并从零积累当前块进度。手动换命令放弃旧任务；重载不重放一次性伐木请求。没有自动补种树苗或森林无限巡采。

## 耕种

支持小麦、胡萝卜、马铃薯、甜菜。只照料现有耕地，不自动锄地、开垦地形或种树。

- 成熟作物：计算一次真实掉落，预留一份同种种子／作物补种，其余放入背包。
- 优先从已有背包扣补种物；不足时可使用这次收获中的实际种子。缺种子或所有余物放不下时，保留原成熟作物。
- 空耕地：从真实背包选取这四种作物的播种物，每格消耗一份。
- 未成熟作物及其他方块保持原状。到达后再次读取世界，两个女仆不会按旧快照重复收获。

候选以最近完成的位置排序，每批最多 16 个参与一次多目标寻路。到位后准备 6 tick 再提交操作，随后继续附近目标。没有工作时逐渐降低扫描频率；背包发生变化会提前唤醒。

本版在现有耕地操作不要求锄头，也不凭空复制收获物。GUI 会提示等待成熟、缺种子、背包不足或不可达。

## 喂养

默认动物标签 `ai-maid-feeding:feedable_animals` 包括牛、哞菇、羊、猪、鸡、兔子、山羊。以原版 `Animal.isFood` 判断饲料，只考虑年龄为 0 且可进入繁殖状态的成年动物。

从真实背包消耗一份合适饲料后调用原版 `setInLove`。寻找配偶、产生幼崽、繁殖条件和冷却仍由动物自己的原版逻辑执行。不会加速幼崽长大、跳过冷却或直接生成幼崽。喂养是给家畜喂食，与 Core 中主人给女仆喂食回血是两件事。

选目标前检查可见性与可操作站位；看得见但进不去的围栏不会长期占住任务。动物移动后重新规划，到位准备 6 tick，完成前再检查距离、资格和饲料。没有饲料会等待补给，补给后自动继续。两只女仆在同一服务器线程依次重新检查目标，一只已喂过后另一只不会再次扣料。标签可扩展，但特殊动物或模组动物仍需单独验证其繁殖规则。

## 铜傀儡式分类搬运

依据本地 26.2 的 `CopperGolemAi`、`TransportItemsBetweenContainers` 源码实现以下规则：

- 来源：任意氧化／涂蜡阶段的铜箱；每次从一格取最多 16 件。
- 目的地：普通箱或陷阱箱；整个箱子为空，或其中已有同种 Item，才允许存入。实际合并必须同时匹配 components。
- 支持原版双箱解析，检查两半的锁及加载状态，拒绝被阻挡的箱子。
- 女仆走近且视线可达后交互 60 tick；正常开合箱盖，保持注视；跳过正在被别人打开的箱子，尝试其他可用箱子。只有忙碌箱子时每 20 tick 重试；没有目标时等待 140 tick；真实路径失败单独冷却 100 tick。

与铜傀儡的主手携带不同，女仆需要**一个空背包槽**存放当前批次货物，主手可以继续持有武器。不会把背包原有杂物自动当作货物清空。

货物 Attachment 只记槽位、种类与未交付数量，真实栈唯一存放在 MaidInventory。它在战斗、换命令、重载后仍可继续交付；死亡按照 Core 背包规则掉落一次。在搬运命令下，Core 的自动换武器和取箭会跳过当前货物格。

没有可用目的地时保留货物并显示原因，不丢在地上，也不凭空“退回”原箱。部分存入后保留实际剩余量。玩家从 GUI 取走／替换货物会使旧凭据失效；新放入的不同物品不会被旧任务运走。玩家手动转移是权威操作，系统不会从凭据重新生成物品。

本版保持选择时的固定区域，不照搬铜傀儡随自身位置不断移动的搜索中心。没有为模组专用机器、领地权限或所有玩家交互事件提供适配；箱子锁与原版双箱规则已覆盖，不代表所有保护模组自动兼容。

## 代码入口与数据流

- Core `entity/combat`：Combat Sensor 每只女仆独立记录伤害事件、目标与失败冷却；FIGHT Activity 执行战斗。
- `MaidCommand.getCombatMode/onCombatStarted/onCombatEnded`：工作声明自卫策略，接收暂停／恢复通知；Core 不引用作物、动物或货物类型。
- `addon/lumber`：LumberCommand、LumberJob、树识别、站位、逐块破坏和动画。
- 其余 Addon：各自 Command 注册 Activity；Data 保存本模组配置与服务端状态；每只 Brain 的 Behavior 保存当前目标、路径计时和短期冷却。
- 状态经现有 MaidStatusPayload 同步至 Menu；物品经标准 Slot 同步，GUI 不复制真实装备或从客户端 Brain 猜工作原因。
