# Core 1.1：共享规则、基础交互与验收

基线：`0e36307`（工作受伤中断）。本轮更新 Core 与 TestAddon 到 1.1.0，并同步 devrun 的依赖版本。发布日期由维护者决定，本轮没有发布制品或提交 Git。

## 本轮行为

1. **装备规则统一**：GUI、自动换装、战斗换手、工作工具保障共用 MaidEquipmentRules。六槽统一检查装备限制；创造模式主人可以取下受限制装备。护甲只放一件，可堆叠装备换装先确认余量和旧装备都能保留。
2. **投喂回血**：主人普通右键投喂，固定恢复 4 点生命，最多回复到最大生命。默认曲奇、苹果、面包；满血不消耗，创造模式不消耗，副手可用。Shift+右键优先开包。支持 USE_REMAINDER，投喂不会把食物的玩家食用效果施加给女仆。
3. **可靠跟随**：主人离线、死亡、处于其他维度或旁观模式时，在 WAIT_FOR_OWNER 中等待。主人可用后恢复跟随。没有修改 FREE、STAY 或工作范围的含义。
4. **具体状态**：GUI 单独一行显示缺工具、装备受限、缺弹药、路径受阻、作业结束/需重选、自卫中、主人不可用、背包满和缺失 Addon 等原因。长文本省略并支持悬停全文；消息来自服务器菜单同步。
5. **公共 API**：新增正确拼写的 selectMaidCommand，保留旧拼写兼容；变更入口检查服务器线程，Brigadier 完成入口重新授权，明确生命周期和短整数协议边界。
6. **独立验收与文档**：Core 有独立的服务端和客户端测试模组，另有两个可选注册入口夹具；生产 JAR 不包含测试实现。README 和模组 metadata 已替换模板内容。

## 跟随归队规则

保持原先超过 10 格开始追赶、4 格以内停止的距离迟滞。连续 100 tick 无接近进展，或原版不可达 Memory 持续 100 tick，进入受阻状态；距离主人至少 12 格才尝试安全传送，失败后每 40 tick 重试。

只在 FOLLOW_OWNER Activity 里执行，因此不会让伐木越过伸手距离，也不会让待命女仆擅自回到主人身边。护卫脱战归队复用此 Activity。

目标必须同维度、存活且非旁观；牵引、乘坐、载客或坐下时暂停追赶。传送时女仆须落地且不在水/岩浆中。检查主人周围水平 2–3 格、垂直 ±1 格的候选位置：区块已加载、世界边界内、WALKABLE、非树叶落脚、无流体且身体无碰撞。不强制加载区块，不跨维度拉人；找不到安全位置就继续等待/寻路。

## 投喂数据包

覆盖或扩展 `data/ai-maid/tags/item/healing_foods.json` 即可改变可投喂物品。所有被接受物品都回复 4 点生命；这是投喂治疗交互，不是复刻玩家食用物品的所有效果。自定义物品的 USE_REMAINDER 会保留。野生女仆的曲奇仍用于概率驯服。
