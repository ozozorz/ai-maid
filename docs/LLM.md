# LLM 调用链与边界

当前版本：LLM 0.3.0、Core / Farming / Lumber 1.3.0；2026-10-20。配置与玩家使用见 [LLM README](../addon/llm/README.md)，动作架构见 [自主任务](AUTONOMOUS_TASKS.md)，实测结果集中在 [验收记录](ACCEPTANCE.md)。

## 普通聊天与工作选择

`MaidChatScreen` 只提交目标UUID、操作和玩家文字。`LlmService` 在服务器线程检查主人、同世界、距离与命令版本，生成真实状态、角色设定、有限历史、命令及动作目录。`LlmClient` 异步发送纯JSON，不在线程池中访问实体或世界。

`ChatProtocol` 校验响应结构、结束原因、工具数量和参数长度；截断输出不执行。回调回服务器线程，再核对会话、同一实体实例、主人和版本。普通聊天每轮最多接受一次工作变更，包括选择模式、固定计划、启动目标或取消；相同请求去重。同一命令重选也递增版本，迟到响应不能覆盖人工操作。

原有 `select_command` 继续经已验证的Registry ID、UUID、整数/枚举构造固定 Brigadier 调用，遵循现有选择政策。没有模型生成JavaScript或任意服务器命令。

## 自主任务反馈循环

1. 普通聊天调用 `start_goal`；参数为空，服务保存玩家本轮原话，有限前文仅作为解释指代的上下文。选中隐藏 PLAN 命令并安装 `MaidGoalTask`，随后结束普通聊天请求链。
2. `GoalDecisionLoop` 持有目标实例、原主人、实体实例和命令版本，读取新状态后异步请求模型。能力目录来自实际加载的动作注册表；专用服务器也有英文语义说明。
3. 模型可以查询或观察，获得绑定女仆/主人的短期目标ID。`ActionTools` 严格校验 JSON 字段和类型，再由 Core 检查物品、数量、位置、类型和真实容器身份。
4. `execute_action` 必须单独调用；提交一个子 `MaidPlanTask` 后保存该工具调用，等待 Brain 执行。不立即返回“成功”，不在每个tick请求模型。
5. 子动作真正结束后，按原 `tool_call_id` 回填冻结的动作记录和新世界状态。失败也包含实际部分转移量。模型依据剩余数量安排后续，或报告阻塞。
6. `finish_goal` 记录模型结论。成功必须已有动作证据且最后动作成功；这不是对任意自然语言目标的形式化证明，动作账本才是实际世界效果的依据。

失败动作达到预算、模型决策次数超限、HTTP失败、运行超时或授权失效均终止。手动切换/取消/重载会同时释放HTTP等待与游戏操作；回调的代际编号和每次消费前的授权检查阻止迟到回复恢复旧目标。

`submit_plan` 仍是固定序列：1..8步预检后顺序执行，失败跳过余下步骤，不进入模型反馈循环。旧小麦配送预设也继续共用动作实现。

## 线程、所有权与上下文

- 世界读写、任务提交、tick与会话变更均在服务器线程；HTTP只持有已构造JSON。
- 启动聊天有距离限制。已接受目标的后续决策允许主人走远，但要求同维度、同所有权、同实体、同任务、同命令版本以及起点范围；不主动加载目标区块。
- 一个女仆只有一个有限任务；模型不能在目标内切换到无限模式或替换目标。不同主人的token和请求记录不互通。
- 每个目标的请求标识覆盖整个生命周期；相同参数重试返回原结果，不再执行，参数冲突拒绝。
- 反馈历史最多12组或48000字符；启动上下文最多16000字符。每次重新提供当前状态与完整有界动作账本，因此裁剪不会丢掉实际交付记录。
- 目标“收集量、存放目的地、是否允许备用箱”等语义仍由模型解释。服务器保证目标来自真实观察、所有权、范围和精确转移，但不声称自动证明模型选中的箱子一定符合自然语言授权。

观察只是一时快照。`path_reachable` 是路径估计，不保证以后可到；真正执行再次检查。动作失败不回滚已发生效果。任务、token与去重不跨重启，避免已完成转移被自动重放。

## 有限资源与显示

每批最多4个工具调用，动作/结束工具独占消息；模型输入上限128Ki字符、HTTP响应体256KiB、输出文字8192字符、动作参数4096字符。配置文件64KiB。普通历史与界面记录分别有限；接口错误只显示有限错误码，不回传远端正文或密钥。

玩家看到的服务器任务状态与模型文字分开。真实数量随动作进展更新，普通进度最多每20tick推送一次，终态立即推送。整个自主目标期间可取消；任务结束后发送恢复可输入的状态。

## 参考与验证范围

早期聊天服务参考 [Touhou Little Maid](https://github.com/TartaricAcid/TouhouLittleMaid) 1.20 分支提交 `8a3ac5e9eacf0c6d63adf8832949f3ce81484fe6` 的每女仆会话、异步HTTP、工具回填与工作选择职责划分，使用本项目 Fabric/MaidCommand API 重写。新的有限动作、目标状态机和结果驱动循环由本项目实现。

自动化用本机模拟模型检验真实HTTP、工具协议、客户端包、Brain移动和世界库存，不等于真实模型任务成功率评测。真实服务验收应增加：不同措辞、连续指代、无成熟作物、箱满且未授权备用箱、资源变化、暂停/取消、失败原因解释，以及调用次数、费用、延迟与成功率。语音、流式输出、向量记忆、跨重启任务恢复、通用合成与无限地图探索尚未实现。
